🚀 QUICK START (10 MINUTES)
═══════════════════════════════════════════════════════════════════════════

1. Read the Quick Deploy Guide:
   👉 QUICK_DEPLOY.md

2. Push to GitHub:
   git init
   git add .
   git commit -m "Air Drawing App"
   git remote add origin https://github.com/YOUR_USERNAME/air-drawing-app.git
   git push -u origin main

3. Deploy Backend to Railway:
   npm install -g @railway/cli
   railway login
   railway init
   railway up

4. Deploy Frontend to Vercel:
   npm install -g vercel
   vercel

5. Set Environment Variables in Vercel:
   NEXT_PUBLIC_BACKEND_URL=https://your-railway-url.railway.app
   NEXT_PUBLIC_WS_URL=wss://your-railway-url.railway.app

6. Done! Your app is live! 🎉

⚠️  IMPORTANT NOTES
═══════════════════════════════════════════════════════════════════════════

1. First OCR Request
   - Takes 30-60 seconds (model downloads ~2GB)
   - Subsequent requests are fast (<5 seconds)
   - This is normal and expected

2. File Storage
   - Training samples won't persist on serverless platforms
   - Use S3 or database for production
   - Or use Railway with persistent volumes

3. WebSocket
   - Automatically uses wss:// (secure) on HTTPS
   - Uses ws:// on HTTP (localhost)
   - Frontend auto-detects backend URL

4. Environment Variables
   - Must be set in Vercel dashboard
   - NEXT_PUBLIC_BACKEND_URL
   - NEXT_PUBLIC_WS_URL

🐛 TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════

WebSocket Connection Failed?
  → Check backend URL in Vercel environment variables
  → Verify backend is running: https://your-backend.railway.app/health

Model Download Timeout?
  → This is normal on first request (30-60 seconds)
  → Subsequent requests are fast

CORS Error?
  → Backend already has CORS enabled
  → Check browser console for actual error

Drawing Lag?
  → Check browser performance
  → Try a different browser

Hand Tracking Fails?
  → Check camera permissions
  → Allow camera access in browser

See VERCEL_DEPLOYMENT_GUIDE.md for detailed troubleshooting
